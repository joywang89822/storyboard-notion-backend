# 參考素材資料庫 使用說明

這是你自己歸檔、自己下 tag 的參考截圖庫，跟公司 Eagle 素材庫索引（`asset_index_中文德撲庫`）是分開的兩份東西。

## 運作邏輯（兩條路）

1. **預設路徑**：寫文字腳本時，Claude 會從每個鏡頭的動作描述/台詞裡抓關鍵字，查 `關鍵字對照表.csv` 轉成標準 tag，再去 `參考素材索引.csv` 用 `subject`（必要時加 `asset_type`）精準比對，**不用 `game` 過濾**（各遊戲版面視覺相近，素材可跨遊戲互通）。找到就直接把檔案放進分鏡；找不到才會回報「資料庫沒有對應素材」，問你要不要用 nano-banana 生圖。
2. **例外路徑**：你直接開口說「幫我截圖」時才用生圖/截圖工具，跟資料庫無關。

## 資料夾結構

```
參考素材資料庫/
  中文德撲/     ← 只給中文德撲用的素材放這裡
  印尼德撲/
  印尼合併/
  Wow_slot/
  通用/         ← 跨遊戲都能用的素材（轉場、文字樣式、通用特效等）
```

截圖直接丟進對應遊戲的資料夾即可，檔名不用刻意取有意義的名字（意義由 tag 承載，不是靠檔名）。

## 填 `參考素材索引.csv`

每加一張截圖，在這張表新增一列。欄位說明：

| 欄位 | 必填 | 說明 |
|---|---|---|
| file_name | 必填 | 檔案名稱（含副檔名） |
| file_path | 必填 | 相對路徑，格式：`遊戲資料夾/檔名`，例如 `中文德撲/ref_火焰牌_01.png` |
| game | 必填，只能選 | 中文德撲／印尼德撲／印尼合併／Wow slot／通用。**只是紀錄素材原始來源用，比對時不當篩選條件**（2026-07-24 起，各遊戲畫面視覺相近，允許跨遊戲互通） |
| asset_type | 必填，只能選 | 場景／UI介面／文字樣式／轉場／片尾／牌桌元件／角色人像／特效／構圖運鏡參考／道具(2026-07-24 從14個合併精簡成10個) |
| subject | **必填，最重要** | 畫面內容主體，**只能填 `關鍵字對照表.csv` 裡已經登記過的標準tag**。如果是全新概念，先去對照表加一行標準詞，再回來這裡填。動作類標準詞刻意拆得很細（All-in動作／跟注動作／加注動作／下注動作／棄牌動作），不要合併成籠統的「動作」 |
| 呈現形式 | 選填但建議填，只能選 | 文字卡／邊框發光／UI面板／籌碼動作／其他。**用意**：同一個 subject 在不同風格下視覺表現不同——例如 all-in 動作，2D 常見是 bar 條特效（UI面板），3D 常見是推籌碼動畫（籌碼動作）；三條特效也可能是純邊框發光、或邊框發光疊加文字卡（例如"3 Kings"）。這欄位就是用來標出「用什麼視覺手法表現」，跟 subject（什麼概念）分開（2026-07-29 新增） |
| 視角 | 選填但建議填，只能選 | 主角／對手／左玩家／右玩家／不指定。**跟 subject 分開的用意**：像「三條特效」這種畫面可能是主角的手牌，也可能是對手的手牌，同一個 subject 會對到好幾張視角不同的圖，只靠 subject 沒辦法區分，選腳本要用哪一張時容易選錯人。3D風格通常只有主角／對手兩種；2D風格玩家較多，用左玩家／右玩家表示座位（2026-07-29 新增，起因：分鏡腳本裡誤把主角視角的畫面用在對手的鏡頭上） |
| character | 選填 | 有固定具名角色才填，例如 荷官_sue |
| style | 選填，只能選 | 3D／2D／真人／真人+2D／AI／塗鴉風（2026-07-29 從「3D擬真／卡通／混合」改成「3D／AI／塗鴉風」，配合實際素材風格；2026-07-29 新增「真人+2D」，專門給畫面一半真人實拍、一半2D遊戲畫面的合成素材，不用另外拆呈現形式欄位） |
| note | 選填 | 自由文字，補充 asset_type/subject 分類覆蓋不到的細節，例如「畫面帶警語版本」「這張的文字排版特別適合當範本」（2026-07-24 重新加回） |

### asset_type 分類定義（2026-07-24）

| 分類 | 定義 | 例子 | 容易搞混的地方 |
|---|---|---|---|
| 場景 | 畫面整體環境/情境鋪陳，呈現「這是什麼地方、什麼情境」 | 辦公室場景、牌桌全景、上班族座位區 | 跟「構圖運鏡參考」的差別：場景是看內容，構圖運鏡參考是看拍法 |
| UI介面 | 遊戲/App 實際操作介面截圖（按鈕、彈窗、選單、設定頁） | 商店頁面、確認彈窗、按鈕樣式 | 廣告影片截幀大多不是遊戲內截圖，除非畫面裡真的出現App介面才選這個 |
| 文字樣式 | 廣告裡的文字排版/字卡/標語動畫設計 | 「ALL IN」字卡動畫、標語文字特效 | 講「字怎麼呈現」，不是講畫面內容 |
| 轉場 | 鏡頭跟鏡頭之間切換的過場效果 | 閃光切換、擦拭轉場、畫面切割轉場 | 是切換瞬間那一幀，不是切換後的畫面 |
| 片尾 | 廣告結尾的收尾畫面 | 品牌LOGO卡、下載按鈕、CTA字卡 | 只限影片最後幾秒的收尾鏡頭 |
| 牌桌元件 | 牌桌上的物件近拍（靜態，沒有特效爆發的瞬間） | 籌碼堆、皇冠頭像框、牌型組合近拍 | 跟「特效」的差別：牌桌元件是東西本身，特效是東西爆發/發光的那個瞬間 |
| 角色人像 | 人物臉部/半身特寫，聚焦表情反應 | 主角驚訝表情、荷官特寫、KOC反應鏡頭 | 只要畫面主體是人的臉/表情就選這個，不管2D/3D/真人 |
| 特效 | 視覺特效爆發的瞬間動態畫面 | 金幣爆炸、光效四射、鐵支/順子出現的閃光 | 是爆發那一刻，平靜狀態的同個物件應歸「牌桌元件」 |
| 構圖運鏡參考 | 不是要畫面裡的東西，是鏡頭角度/運鏡手法值得之後仿造 | 低角度仰拍、第一人稱瞇牌視角、分割畫面 | 重點是怎麼拍，內容其實不重要 |
| 道具 | 非牌桌相關的具體物件 | 釣魚竿（看我釣大魚篇）、手機、辦公用品 | 牌桌上的東西一律算「牌桌元件」，不算道具 |

（原本還有 `id`、`motion`、`source`、`note`、`date_added` 幾欄，2026-07-24 精簡掉了，只保留辨識/篩選必要的欄位。）

**兩條硬規則（避免比對抓錯）：**
- `game`、`asset_type` 只能從上面列的固定選項選，不要自己造新詞（要新增選項，先跟 Claude 說一聲，一起決定要不要擴充）。
- `subject` 必須是 `關鍵字對照表.csv` 裡的標準詞，不要自己想到什麼就填什麼——不然腳本寫「金幣」、你填「硬幣」，兩邊對不起來就會抓不到。

## 填 `關鍵字對照表.csv`

這張表是「腳本常見寫法」跟「標準tag」的翻譯表。每次遇到一個新的內容主體，先在這裡登記一行：

- 左欄：把所有可能在腳本裡出現的同義詞、口語寫法都列出來（用頓號分隔）
- 中欄：定一個唯一的標準tag，之後 `subject` 欄一律填這個詞
- 右欄：備註，尤其是容易混淆的相似詞要註明差異（例如已經內建的「鐵支／三條」提醒）

新詞越早登記、越詳細，之後比對越準。已經先幫你放了幾個德州撲克常見的例子（金幣、all-in、牌型特效等），你可以直接照這個格式往下加。

## 給 Claude 的比對規則備忘

- 比對時直接用 `subject` 精準比對，不做模糊字串比對，**不用 `game` 過濾**（2026-07-24 起：各遊戲畫面視覺相近，素材可跨遊戲互通；`game` 只是紀錄來源用）。
- 動作描述裡如果講明是誰的動作/手牌（主角／對手／左右玩家），比對時要連 `視角` 一起篩，不能只看 `subject` 就選（2026-07-29 新增，同一個 subject 常常主角、對手都各有一張，選錯人畫面會誤導劇情）。
- 找到多筆符合時，列出來讓你選，不會自己猜一個放進去。
- 完全沒有符合的素材時，明確告訴你「資料庫目前沒有『XX』的參考素材」，不會用相近的湊數。
- **風格（`style`）不符時視同「沒有對應素材」**，不能用別的風格湊數當參考圖（2026-07-29 新增：曾經在3D案子裡放2D素材當參考，造成畫面風格突兀）。
  - **例外**：品牌片尾類（`中撲jingle`、`印撲icon`）不受此限制，2D/3D等風格皆可直接用，不用比對 `style`（2026-07-29 新增，使用者說明片尾素材不分風格）。
